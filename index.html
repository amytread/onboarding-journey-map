What real onboardings show · grounded in 5 recent onboarding sessions, May–Jun 2026
  • Avoid parent/child unless data must be truly separated. It adds setup complexity and users land in the wrong account; billing at the parent level isn't handled well. Only split when data genuinely must be sequestered (e.g. a two-state hauler; a construction customer's subsidiary). If unavoidable, decide before inviting users and watch for lingering ex-employee logins.
  • Sandbox vs Production trips teams up. One customer's admin was on Sandbox; vendor invites sent there don't count. Migrate to production first.
  • Vendor onboarding is its own project. 50–60 mostly 2–3-truck vendors; invites must go out days ahead — bulk-uploaded or Tread-sent on the customer's behalf — and the setup form needs to work on mobile (one customer built an HTML one).
  • Phase-code compliance is the construction pain. One contractor loses six figures to unallocated costs; no hard gate yet, so it's SOP + exception report. Foreman set at order level; drivers can edit their hours.
  • Go-live is high-touch and fast. ~2-week timelines; Tread flies out for on-site train-the-trainer sessions covering dispatchers, foremen and vendors together.
  • Graduation is now formal. "Tread University" certifies trained customers (a returning customer is lined up as the first graduate), fed by a sales→onboarding handover doc. But baseline readiness is low — some users still can't log in.
